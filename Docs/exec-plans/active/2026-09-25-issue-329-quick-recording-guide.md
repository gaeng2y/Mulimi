# #329 빠른 물 기록 가이드 제작·발행

## Context

- [#329](https://github.com/gaeng2y/Mulimi/issues/329)의 가이드 원고와 커뮤니티 요약을 준비한다. 상위 실험은 [#284](https://github.com/gaeng2y/Mulimi/issues/284), 촬영 자산은 [#328](https://github.com/gaeng2y/Mulimi/issues/328), ASO는 [#327](https://github.com/gaeng2y/Mulimi/issues/327)에서 관리한다.
- 코드 확인 기준: `develop`의 `04ab8f549ef4c98237756d9c83a27a7144d98892`. 저장소 구현 확인이며 App Store 배포 확인이 아니다.
- 2026-09-25 사용자 확인: 게시할 블로그·커뮤니티와 게시 예정일은 미정이다. 실제 게시·기기 검증·초보자 확인은 아직 수행하지 않았다.

## Goal

독자가 자기에게 맞는 방법 하나를 설정하고 실제 첫 기록에 성공하도록 안내한다. 캠페인 다운로드와 안내의 사용성을 따로 관찰한다.

## Non-Goals

새 앱 기능·랜딩 사이트·설정 도구·분석 SDK·유료 광고를 추가하지 않는다. 이 제작 PR로 실제 게시나 28일 실험을 완료 처리하지 않는다.

## Constraints

- 홈 화면 위젯의 직접 기록과 일반 잠금 화면 위젯의 섭취량 표시를 구분한다. 제어 센터·잠금 화면 Control·액션 버튼은 공개 가이드에서 제외한다.
- 공개할 각 경로는 App Store에서 설치한 버전으로 확인한다. 코드·시뮬레이터·TestFlight 결과를 그 대신 사용하지 않는다.
- 건강 기록은 기기에서만 확인하고 참여자의 원본 건강 화면, 건강 수치, 계정 식별자를 실행 기록에 모으지 않는다. 안내 이미지에는 본인이 관리하는 데모 자료를 사용한다.
- 기록량·권한·목표 초과·저장 실패 문구는 [수분 기록 정책](../../product-specs/hydration-logging.md)을 따른다. 사용자 원고에 내부 구현 설명을 넣지 않는다.

## Plan

1. [가이드 초안](../../marketing/quick-recording-guide.md), 아래 커뮤니티 원고와 자산 목록을 검토한다.
2. 채널·담당자·일정을 확정하고 실제 설치본의 각 경로를 검증한다.
3. 초보자 1명 이상에게 방법 하나를 골라 따라 하게 하고 막힌 단계를 고친다.
4. 검증된 캡처와 캠페인 링크를 넣고 가이드 1개·커뮤니티 요약 1개를 게시한다.
5. 실제 가이드 게시일로부터 28일 후 회고한다. PR은 `Related to #329`로 연결하고 이슈는 계속 열어 둔다.

## First-Use Check

처음 사용하는 사람 1명 이상에게 가이드만 제공한다. 선택표를 읽기 시작한 순간부터 선택한 경로의 첫 저장을 확인할 때까지 시간을 잰다. 중간 도움을 주었다면 그대로 남긴다. 실패·중단은 중단까지의 시간을 기록하고, 소수 관찰을 통계적 효과나 전환율 검증으로 보고하지 않는다.

| 확인일 / 원고 버전 | 선택 경로 / 기기·OS·앱 버전 | 결과 | 소요 시간 | 막힌 단계·도움 여부 | 원고 보완 |
| --- | --- | --- | --- | --- | --- |
| 미실시 | 미확인 | 미확인 | 미측정 | 미확인 | 대기 |

결과는 `자력 성공 / 도움 후 성공 / 실패 / 미확인` 중 하나다. 시도 인원과 각 결과 인원을 함께 기록하고 실패·미확인을 분모에서 빼지 않는다. 앱 안에서 빠른 기록 방법을 선택했다는 상태는 위젯 설치나 실제 저장의 증거가 아니다.

## Community Draft

아래 원고는 검증·규칙 확인 후 게시한다. 가이드 주소가 확정되면 마지막 편집용 주석을 실제 링크로 바꾼다.

### 제목: 아이폰에서 물 기록, 홈 화면·워치·Siri 중 편한 방법 하나 설정하기

안녕하세요. 수분 기록 앱 물리미를 개발하고 있습니다. 물을 마신 뒤 기록할 때 쓸 수 있는 세 가지 방법을 정리했습니다.

- **홈 화면에서:** 빈 곳 길게 누르기 → 편집 → 위젯 추가 → 물리미의 작은 `물 마시기` 위젯을 추가합니다. 위젯의 `마시기` 버튼으로 기본 한 잔을 기록합니다.
- **손목에서:** iPhone Watch 앱 → 나의 시계에서 물리미를 설치한 뒤, Watch의 물리미 앱에서 기록합니다.
- **목소리로:** iPhone에서 Siri에게 “물리미에서 물 기록”이라고 말합니다. 단축어 앱에서는 물리미의 `물 기록`을 실행할 수 있습니다.

iOS 26 이상, Watch는 watchOS 26 이상이 필요합니다. 처음에는 물리미에서 로그인·초기 설정과 건강 앱 수분 권한을 확인해 주세요. 위젯과 Watch의 기본 한 잔은 250ml이고, 다른 양은 단축어에서 선택할 수 있습니다. 일반 잠금 화면 위젯은 오늘 섭취량 확인용입니다.

자주 쓸 방법 하나만 골라 시작해 보세요. 권한 확인이나 잠금 해제가 필요할 수 있고, 목표를 넘는 양은 기록되지 않습니다. 실행 후 물리미와 건강 앱에서 실제 기록을 확인하는 순서까지 가이드에 담았습니다.

가이드대로 설정한 뒤 오늘 첫 잔을 기록해 보세요.

## Measurement And Effort

측정 정의와 판정은 [Growth Scorecard](../../product-specs/growth-scorecard.md)의 Experiment Record를 사용한다. 1차 지표는 가이드 캠페인의 최초 다운로드, 보조 지표는 제공되는 조회·클릭·반복 설정 질문이다. 첫 회차는 기준선 수집으로 남긴다.

- 캠페인 링크는 App Store Connect에서 생성하고 실제 게시월에 맞춰 이름을 정한다. Apple의 최소 표시 기준은 성공 기준이 아니다. 숨겨진 값은 `측정 불가`, 아직 수집하지 않은 값은 `미측정`으로 기록한다. [Apple 캠페인 링크 안내](https://developer.apple.com/help/app-store-connect-analytics/acquisition/campaign-links)
- 채널 지표·App Store 집계·PostHog 제품 지표를 사용자 단위로 결합하지 않는다. 같은 블로그를 거친 커뮤니티 유입의 최종 설치를 커뮤니티별로 구분하지 않는다.
- Widget·Watch의 PostHog 수집은 불완전하다. 앱 이벤트가 없다는 이유로 사용 실패를 단정하지 않고, 위 따라 하기 기록으로 안내의 사용성을 확인한다.
- 보고 시각은 KST로 적고 App Store 집계의 원본 시간대·날짜 범위를 함께 보관한다. 집계된 일별 값을 임의로 KST로 변환하지 않는다.

| 작업 | 계획 | 실제 공수·근거 |
| --- | --- | --- |
| 기존 촬영 자산을 이용한 원고 제작·게시 | 2~3시간 | 미집계 — 작업 시작 2026-09-25, 확정 전 |
| 추가 촬영·기기 검증·초보자 확인·수정 | 별도 기록 | 미실시 |
| 관찰·28일 회고 | 별도 기록 | 미실시 |

회고에는 다운로드·조회·클릭 원시 수치와 출처, 따라 하기 시도/성공/도움/실패/미확인 인원, 반복 질문, 실제 공수, 측정 한계와 동시 변경을 남긴다. `확대 / 개선 후 재실험 / 중단 / 판정 보류` 중 하나와 다음에 보완할 경로 하나를 선택한다. 검색 노출·배포가 부족하면 키워드 실패로 단정하지 않는다.
